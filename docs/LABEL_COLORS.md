## Usage Guidelines

### Issue-Type Labels
Use these labels to categorize the type of work being requested or reported:
- **bug**: Use for reporting bugs, errors, or issues that prevent expected functionality
- **enhancement**: Use for suggesting improvements or feature additions
- **feature**: Use for specific feature implementations
- **task**: Use for specific tasks or sub-tasks within larger issues
- **question**: Use when you need clarification or additional information
- **wontfix**: Use when an issue will not be addressed
- **documentation**: Use for documentation improvements and additions

### Area Labels
Use these labels to specify which part of the codebase is affected:
- **frontend**: Use for changes to the user interface and client-side code
- **backend**: Use for server-side logic and database changes
- **platform**: Use for cross-platform functionality
- **hooks**: Use for hook-related implementations and issues
- **context**: Use for context management and memory context issues

### Platform Labels
Use these labels when an issue is specific to a particular platform:
- **macOS**: Use for issues specific to macOS platform
- **iOS**: Use for issues specific to iOS platform
- **web**: Use for issues specific to web browsers

### Status Labels
Use these labels to track the status of an issue:
- **critical**: Use for high-priority issues that need immediate attention
- **in-progress**: Use when work has started on the issue
- **blocked**: Use when an issue cannot be progressed due to external dependencies
- **needs-review**: Use when code or changes are ready for review
- **needs-approval**: Use when approval is required before proceeding
- **wip**: Use when work is actively in progress
- **waiting-on-decision**: Use when awaiting a decision before work can continue

### Performance Labels
Use these labels for performance-related issues:
- **memory**: Use for memory-related bugs, leaks, or optimization needs

### Priority Labels
Use these labels to indicate priority level:
- **good-first-issue**: Use for issues suitable for newcomers or first-time contributors
- **help-wanted**: Use for issues that need additional assistance or volunteers
- **hotfix**: Use for urgent fixes that need to be deployed quickly
