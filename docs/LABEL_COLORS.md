This document provides a comprehensive guide to the label organization in the repository, designed to improve visual organization and streamline issue triage.

## Usage Guidelines

### Issue-Type Labels
Use these labels to categorize the nature of the issue:
- **bug**: Use for actual bugs or defects in the software
- **feature**: Use for new feature requests
- **task**: Use for tasks or subtasks that need to be completed
- **enhancement**: Use for improvements to existing features
- **question**: Use when more information is needed from the reporter

### Status Labels
Use these labels to track the current state of work:
- **in-progress**: Use when work has started but is not complete
- **blocked**: Use when work cannot proceed due to dependencies or other blockers
- **wip**: Use for work in progress that may not be complete yet
- **waiting-on-decision**: Use when waiting for input or decisions from stakeholders
- **needs-review**: Use when code or documentation needs review before merging
- **needs-approval**: Use when approval is required before proceeding

### Platform Labels
Use these labels to indicate platform-specific issues:
- **macOS**: Use for issues or features specific to macOS
- **iOS**: Use for issues or features specific to iOS
- **web**: Use for issues or features specific to web platforms
- **platform**: Use for general platform-related issues that affect multiple platforms

### Area Labels
Use these labels to categorize by the area of the codebase or system:
- **memory**: Use for issues related to memory management, leaks, or optimization
- **context**: Use for issues related to context management or state
- **hooks**: Use for issues related to hook execution or integration
- **frontend**: Use for frontend UI or client-side issues
- **backend**: Use for backend server-side issues
- **testing**: Use for testing-related issues, test failures, or test coverage

### Priority Labels
Use these labels to indicate urgency or importance:
- **critical**: Use for issues that require immediate attention and may cause significant impact
- **hotfix**: Use for urgent fixes that need to be deployed quickly

### Contribution Labels
Use these labels to encourage community participation:
- **good-first-issue**: Use for issues that are good for newcomers to contribute to
- **help-wanted**: Use for issues where community help is specifically needed

### Documentation Labels
- **documentation**: Use for issues or PRs related to documentation improvements

### Other Labels
- **wontfix**: Use for issues that will not be addressed or fixed

---

This label guide is designed to improve visual organization and make issue triage more efficient. Consistent use of these labels will help team members quickly understand the nature and status of issues.
