## Usage Guidelines

### Issue Type Labels
Use **issue-type** labels to classify the nature of the issue:
- **bug**: Apply to any non-working behavior or defects
- **enhancement**: Apply to requests for new features or improvements
- **feature**: Apply to new functionality being added
- **task**: Apply to specific tasks or work items
- **question**: Apply when clarification is needed
- **wontfix**: Apply to issues that will not be addressed
- **documentation**: Apply to documentation-related work

### Priority Labels
Use **priority** labels to indicate urgency:
- **critical**: Use for severe issues requiring immediate attention
- **hotfix**: Use for urgent production fixes

### Difficulty Labels
Use **difficulty** labels for contributor engagement:
- **good-first-issue**: Apply to beginner-friendly issues
- **help-wanted**: Apply to issues needing additional assistance

### Platform Labels
Use **platform** labels to specify target platforms:
- **macOS**: For macOS-specific issues
- **iOS**: For iOS-specific issues
- **web**: For web browser-related issues

### Area Labels
Use **area** labels to categorize by component/domain:
- **frontend**: Frontend UI and client-side code
- **backend**: Server-side and API development
- **hooks**: Hook-related functionality
- **platform**: Platform integration and setup
- **memory**: Memory management and optimization
- **context**: Context and state management
- **testing**: Testing infrastructure and validation

### Status Labels
Use **status** labels to track progress:
- **in-progress**: Active work being done
- **blocked**: Waiting on external dependencies
- **needs-review**: Ready for code/review
- **needs-approval**: Requires approval before proceeding
- **wip**: Work in progress (alternative to in-progress)
- **waiting-on-decision**: Awaiting stakeholder decision

---

This guide ensures consistent labeling across all issues and pull requests for improved organization and discoverability.
